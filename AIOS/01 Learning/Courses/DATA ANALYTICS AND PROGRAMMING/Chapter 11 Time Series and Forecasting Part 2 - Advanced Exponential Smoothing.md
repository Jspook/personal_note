## Part 1: Macro Architecture & Overview

บทนี้ครอบคลุมเทคนิคการทำให้เรียบ (Smoothing Methods) 2 ตระกูลตามสไลด์: **Averaging Methods** (Simple / Weighted / Double Moving Average) และ **Exponential Smoothing** (Single / Double / Triple) โดยต่อยอดจากบท 10 — เมื่อข้อมูล Time Series มี Trend แบบเชิงเส้น และ/หรือ Seasonality ที่ชัดเจน วิธีการอย่างง่ายเช่น Moving Average ไม่เพียงพอ ต้องใช้วิธีการถ่วงน้ำหนักแบบ Exponential ที่ยืดหยุ่นมากขึ้น เพื่อจับรูปแบบและพยากรณ์อนาคตได้แม่นยำกว่า

```text
Smoothing Methods
├── Averaging Methods (น้ำหนักเท่ากัน / กำหนดเอง)
│   ├── Simple Moving Average     (Horizontal)
│   ├── Weighted Moving Average   (Horizontal, ให้น้ำหนักข้อมูลใหม่มากกว่า)
│   └── Double Moving Average     (Linear Trend)
│
└── Exponential Smoothing (น้ำหนักลดแบบ Exponential)

Data Classification (Exponential)
├── Horizontal Pattern (ระดับคงที่)
│   └── Single Exponential Smoothing
│
├── Linear Trend (แนวโน้มเชิงเส้น)
│   └── Double Exponential Smoothing (Brown's Method)
│
└── Trend + Seasonality (แนวโน้ม + ฤดูกาล)
    └── Triple Exponential Smoothing (Holt-Winters)
        ├── Multiplicative Form (ฤดูกาลแปรผันตามระดับ)
        └── Additive Form (ฤดูกาลคงที่)
```

> 💡 **Recommended Tool for Conversion:** Mermaid (Decision Tree / Classification Flowchart)

### ตารางเปรียบเทียบวิธีการเรียบแบบ Exponential

| วิธี | ลักษณะข้อมูล | พารามิเตอร์ | สูตรหลัก | เหมาะกับ |
| :--- | :--- | :--- | :--- | :--- |
| **Simple Moving Average** | Horizontal | N | Fₜ₊₁ = (Yₜ+…+Yₜ₋ₙ₊₁)/N | ไม่มี Trend/Seasonality |
| **Weighted Moving Average** | Horizontal | น้ำหนัก wᵢ (รวม = 1) | Fₜ₊₁ = Σ wᵢYₜ₋ᵢ₊₁ | ข้อมูลใหม่สำคัญกว่า |
| **Double Moving Average** | Linear Trend | N | Fₜ₊ₘ = aₜ + bₜ(m) | มี Trend เชิงเส้น |
| **Single Exponential** | Horizontal (ไม่มี Trend) | α (0 < α < 1) | Fₜ₊₁ = αYₜ + (1-α)Fₜ | ข้อมูลมีค่าคงที่ |
| **Double Exponential (Brown)** | Linear Trend | α (0.05-0.1) | Fₜ₊ₘ = aₜ + bₜ(m) | ข้อมูลมี Trend แนวโน้ม |
| **Triple Exponential (Holt-Winters)** | Trend + Seasonality | α, β, γ | Fₜ₊ₘ = (Lₜ + bₜm)Sₜ₋ₛ₊ₘ | ข้อมูลมี Trend และ Seasonality |

## Part 2: Module-by-Module Deep Dive

### 2.1 Simple Moving Average (เฉลี่ยเคลื่อนที่อย่างง่าย)

> 💡 **Intuition:** ลองนึกว่าดูค่าเฉลี่ยของ 3 วันล่าสุดเพื่อประเมินภาพรวม เมื่อวันใหม่เข้ามา วันที่เก่าที่สุดจะหลุดออกจากการคำนวณ ค่าเฉลี่ยจึง "เคลื่อนที่" ไปตามเวลา แต่จำนวนวันที่ใช้เฉลี่ย (N) คงที่ เหมาะกับข้อมูลที่แกว่งรอบระดับเดิม จุดที่อุปมาจะพัง: ถ้าข้อมูลมี Trend ค่าที่ได้จะตามหลังอยู่เสมอ และ MA จับ Seasonality ไม่ได้
> [Source: generated — not verified against original document]

> เมื่อข้อมูลช่วงเวลาล่าสุดเข้ามา ข้อมูลที่เก่าที่สุดจะถูกตัดออก ทำให้จำนวนเทอมที่เฉลี่ย (N) คงที่ทุกครั้ง เหมาะกับข้อมูลที่เคลื่อนไหวรอบระดับคงที่ (**Horizontal Pattern**) ไม่มี Trend หรือ Seasonality ที่ชัดเจน

```text
รูปแบบข้อมูล:  Yₜ = ค่าคงที่ + ความคลาดเคลื่อน ณ เวลา t

STEP 1: กำหนดจำนวนเทอม N
STEP 2: Fₜ₊₁ = (Yₜ + Yₜ₋₁ + … + Yₜ₋ₙ₊₁) / N
```

**ตัวอย่างจากสไลด์ (N = 3, ยอดขายหน่วยแสนบาท)**

| t | Yₜ | Fₜ (MA3) | Eₜ | \|Eₜ\| | Eₜ² | \|Eₜ/Yₜ\| |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 5.4 | - | | | | |
| 2 | 5.3 | - | | | | |
| 3 | 5.3 | - | | | | |
| 4 | 5.6 | 5.33 | 0.27 | 0.27 | 0.07 | 0.05 |
| 5 | 6.9 | 5.40 | 1.50 | 1.50 | 2.25 | 0.22 |
| 6 | 7.2 | 5.93 | 1.27 | 1.27 | 1.60 | 0.18 |
| 7 | 7.2 | 6.57 | 0.63 | 0.63 | 0.40 | 0.09 |
| 8 | - | 7.10 | | | | |
| รวม | | | 3.67 | 3.67 | 4.33 | 0.53 |

```text
F₄ = (Y₃+Y₂+Y₁)/3 = (5.3+5.3+5.4)/3 = 5.33
F₈ = (Y₇+Y₆+Y₅)/3 = (7.2+7.2+6.9)/3 = 7.10  → ยอดขายไตรมาส 8 ≈ 710,000 บาท
ME = MAE = 3.67/4 = 0.92,  MSE = 4.33/4 = 1.08,  MAPE = 0.53/4 ≈ 0.13
```

**การเลือก N:** N เล็ก = ตอบสนองเร็วแต่ผันผวน | N ใหญ่ = เรียบแต่ตอบสนองช้า

**🧭 ทำความเข้าใจ** _[Source: generated — not verified against original document]_

**แตกวลีสำคัญ:**
- "N (จำนวนเทอม)" → จำนวนข้อมูลล่าสุดที่นำมาเฉลี่ยในทุกรอบ (ตัวอย่างนี้ N = 3)
- "Fₜ₊₁ = (Yₜ + ... + Yₜ₋ₙ₊₁) / N" → เฉลี่ยข้อมูล N ตัวล่าสุด แล้วใช้เป็นค่าพยากรณ์ของช่วงถัดไป
- "Horizontal Pattern" → ข้อมูลแกว่งรอบระดับคงที่ ไม่มี Trend หรือ Seasonality ที่ชัด

**ตัวอย่าง:**
- ✅ F₄ = (5.4 + 5.3 + 5.3) / 3 ≈ 5.33 ตรงกับตาราง → คำนวณถูกต้องตามสูตร
- ❌ ใช้ MA(3) แล้วคาดว่า F₅ จะตาม Y₅ = 6.9 ทัน → ไม่ทัน เพราะ F₅ = 5.40 ใช้ Y₂–Y₄ เท่านั้น ข้อมูลที่กระโดดจึงยังไม่ถูกนำมาใช้ (ตอบสนองช้า)
- **ต่างกันตรง:** ดูว่าข้อมูลแกว่งรอบระดับคงที่หรือมี Trend/Seasonality ถ้ามี MA ไม่เหมาะ

**อย่าสับสน:** "N" ไม่ใช่จำนวนข้อมูลทั้งหมด แต่คือจำนวนข้อมูลล่าสุดที่เลือกมาเฉลี่ย (ตัวอย่างนี้มีข้อมูลหลายจุดแต่ N = 3)

**เช็คความเข้าใจ:** จากตาราง MA(3) ค่า F₅ = 5.40 ถูกคำนวณจาก Y ตัวใด และทำไมค่า Y₅ = 6.9 จึงยังไม่มีผลต่อ F₅

<details><summary>เฉลย</summary>

F₅ = (Y₄ + Y₃ + Y₂) / 3 = (5.6 + 5.3 + 5.3) / 3 = 5.40 Y₅ ยังไม่ถูกใช้ในการพยากรณ์ F₅ (จะเข้าไปใช้ตั้งแต่ F₆) ทำให้ MA ตอบสนองช้าเมื่อข้อมูลกระโดด
</details>

### 2.2 Weighted Moving Average (เฉลี่ยเคลื่อนที่ถ่วงน้ำหนัก)

> 💡 **Intuition:** ลองนึกถึงการเดาอารมณ์เพื่อนจากข้อความ 3 ข้อความล่าสุด ข้อความล่าสุดบอกอารมณ์ตอนนี้ได้ดีกว่าข้อความเมื่อ 3 วันก่อน จึงให้ความสำคัญข้อความใหม่มากกว่า Weighted MA ทำแบบเดียวกัน คือให้น้ำหนักข้อมูลใหม่มากกว่าข้อมูลเก่า ทำให้ forecast ตามข้อมูลทัน โดยเฉพาะเมื่อมี Trend จุดที่ analogy ไม่ตรง: คนให้น้ำหนักตามความรู้สึก แต่ใน Weighted MA น้ำหนักต้องกำหนดเป็นตัวเลขชัดเจน และผลรวมต้องเท่ากับ 1
> [Source: generated — not verified against original document]

> กำหนดน้ำหนักให้ข้อมูลแต่ละช่วงต่างกัน โดยให้ข้อมูลล่าสุดมากกว่าข้อมูลอดีต และ **ผลรวมน้ำหนักต้องเท่ากับ 1**

สไลด์ใช้ N = 3 ไตรมาส ด้วยน้ำหนัก 0.2 (ไกลสุด), 0.3 (กลาง), 0.5 (ใกล้ปัจจุบัน)

```text
F₄ = (5.4×0.2) + (5.3×0.3) + (5.3×0.5) = 5.32
F₈ = (6.9×0.2) + (7.2×0.3) + (7.2×0.5) = 7.14  → ≈ 714,000 บาท
```

| t | Yₜ | Fₜ (WMA3) | Eₜ | \|Eₜ\| | Eₜ² | \|Eₜ/Yₜ\| |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 4 | 5.6 | 5.32 | 0.28 | 0.28 | 0.08 | 0.05 |
| 5 | 6.9 | 5.45 | 1.45 | 1.45 | 2.10 | 0.21 |
| 6 | 7.2 | 6.19 | 1.01 | 1.01 | 1.02 | 0.14 |
| 7 | 7.2 | 6.79 | 0.41 | 0.41 | 0.17 | 0.06 |
| 8 | - | 7.14 | | | | |
| รวม | | | 3.15 | 3.15 | 3.37 | 0.46 |

```text
ME = MAE = 3.15/4 = 0.79,  MSE = 3.37/4 = 0.84,  MAPE = 0.46/4 ≈ 0.11
```

เทียบกับ Simple MA (MAE 0.92, MSE 1.08, MAPE 0.13) → WMA แม่นกว่าในชุดข้อมูลนี้ เพราะข้อมูลมี Upward Trend

**🧭 ทำความเข้าใจ** _[Source: generated — not verified against original document]_

**แตกวลีสำคัญ:**
- "ผลรวมน้ำหนักต้องเท่ากับ 1" → น้ำหนักทั้งหมดรวมกันเป็น 100% เหมือนค่าเฉลี่ย ถ้าเกิน 1 ค่า forecast จะสูงเกินจริง
- "ข้อมูลล่าสุดมากกว่า" → น้ำหนักที่ใกล้ปัจจุบันที่สุด (0.5) มากกว่าน้ำหนักไกลสุด (0.2)

**ตัวอย่าง:**
- ✅ น้ำหนัก 0.2, 0.3, 0.5 (รวม = 1.0) — ถูกต้อง และข้อมูลใหม่มีผลมากสุด
- ❌ น้ำหนัก 0.5, 0.4, 0.3 (รวม = 1.2) — ผิด เพราะรวมเกิน 1 ทำให้ค่าเฉลี่ยพองเกินจริง
- **ต่างกันตรง:** Simple MA ให้ทุกช่วงน้ำหนักเท่ากัน (1/N) ส่วน Weighted MA ให้ผู้ใช้กำหนดน้ำหนักเอง

**อย่าสับสน:** "N = 3" หมายถึง ใช้ข้อมูลย้อนหลัง 3 ช่วงเวลา ไม่ได้หมายถึงน้ำหนักมี 3 ค่าที่เท่ากัน

**เช็คความเข้าใจ:** ใช้น้ำหนัก 0.2, 0.3, 0.5 กับ Y₂ = 5.3, Y₃ = 5.3, Y₄ = 5.6 จงหา F₅
<details><summary>เฉลย</summary>

F₅ = (5.3×0.2) + (5.3×0.3) + (5.6×0.5) = 1.06 + 1.59 + 2.80 = 5.45

ตรงกับค่า F₅ = 5.45 ในตาราง น้ำหนัก 0.5 อยู่ที่ข้อมูลล่าสุด (Y₄)
</details>

### 2.3 Double Moving Average (เฉลี่ยเคลื่อนที่ทวิ)

> 💡 **Intuition:** ลองนึกว่า Simple Moving Average ทำงานได้ไม่ดี เมื่อข้อมูลมี Trend (เพิ่มขึ้นหรือลดลงติดต่อกัน) เพราะมันทำให้ค่า forecast ล่าช้า (Lag) Double Moving Average แก้ปัญหานี้โดยการ "เรียบสองครั้ง" — เรียบครั้งแรกเหมือนปกติ แล้วเรียบผลลัพธ์นั้นอีกครั้ง ด้วยการเรียบสองครั้ง สามารถจับ Trend (ความชัน) ของข้อมูลได้ จึงยื่นค่าพยากรณ์ไปตาม Trend ได้ ไม่ล่าช้าเหมือน Simple MA
> [Source: generated — not verified against original document]

> คำนวณ Simple Moving Average 2 ครั้ง: ครั้งแรกจากข้อมูลจริง ครั้งที่สองจากค่าที่ได้ครั้งแรก ใช้ N เท่ากันทั้งสองครั้ง เหมาะกับข้อมูลที่มี **Linear Trend**

**🧭 ทำความเข้าใจ** _[Source: generated — not verified against original document]_

**แตกวลีสำคัญ:**
- "เรียบสองครั้ง" → ครั้งแรกจากข้อมูลจริง (Sₜ⁽¹⁾) ครั้งที่สองจากผลของครั้งแรก (Sₜ⁽²⁾) = ทำให้ "เรียบยิ่งขึ้น" และ "จับ Trend ได้"
- "aₜ" → ระดับปัจจุบัน (Level / Base) ของข้อมูล
- "bₜ" → ความชัน (Slope) = อัตราการเปลี่ยนแปลง (ต่อช่วงเวลา)
- "Fₜ₊ₘ = aₜ + bₜ·m" → ทำนาย m ก้าวข้างหน้า = ระดับปัจจุบัน + (ความชัน × จำนวนก้าว)

**ตัวอย่าง:**
- ✅ ข้อมูลยอดขาย = [362, 385, 432, 341, ...] มี Trend ↑ → Double MA ได้ a₇ = 424.13, b₇ = 11.08 → F₈ = 424.13 + 11.08(1) = 435.21 เล่ม
- ❌ ข้อมูลไม่มี Trend (ขึ้นลงแบบสุ่ม) → Double MA จะประมาณ bₜ จาก noise (Trend ที่ไม่มีจริง) แล้วยื่นต่อไปข้างหน้า → ทำนายเกิน/ขาด ควรใช้ Simple MA หรือ Single Exponential แทน
- **ต่างกันตรง:** Simple MA ทำนายเป็นค่าเฉลี่ยอดีต จึงตามหลัง Trend (Lag) Double MA ทำนายตามแนวโน้ม (ชัน)

**อย่าสับสน:** "Double" ≠ "เรียบสองเท่า" — "Double" หมายถึง "คำนวณ MA สองครั้ง" เพื่อจับ Trend ได้ดีขึ้น

**เช็คความเข้าใจ:** ข้อมูล = [10, 15, 20, 25] N=2 Double MA คำนวณ S⁽¹⁾ และ S⁽²⁾ สำหรับ t=4
<details><summary>เฉลย</summary>

**ครั้งแรก (Simple MA):**
- S₂⁽¹⁾ = (15 + 10) / 2 = 12.5
- S₃⁽¹⁾ = (20 + 15) / 2 = 17.5
- S₄⁽¹⁾ = (25 + 20) / 2 = 22.5

**ครั้งที่สอง (MA of MA):**
- S₃⁽²⁾ = (17.5 + 12.5) / 2 = 15
- S₄⁽²⁾ = (22.5 + 17.5) / 2 = 20

**คำตอบ:** S₄⁽¹⁾ = 22.5 และ S₄⁽²⁾ = 20
</details>

```text
รูปแบบข้อมูล:  Yₜ = a + bt + ความคลาดเคลื่อน

STEP 1: กำหนด N
STEP 2: Sₜ⁽¹⁾ = (Yₜ + Yₜ₋₁ + … + Yₜ₋ₙ₊₁) / N
        Sₜ⁽²⁾ = (Sₜ⁽¹⁾ + Sₜ₋₁⁽¹⁾ + … + Sₜ₋ₙ₊₁⁽¹⁾) / N
STEP 3: aₜ = 2Sₜ⁽¹⁾ − Sₜ⁽²⁾
        bₜ = [2/(N−1)] · [Sₜ⁽¹⁾ − Sₜ⁽²⁾]
STEP 4: Fₜ₊ₘ = aₜ + bₜ·m
```

**ตัวอย่างจากสไลด์:** ยอดขายหนังสือ 20 ไตรมาส (ไตรมาส 1-4 = 362, 385, 432, 341), N = 4, พยากรณ์ไตรมาส 21

```text
S₄⁽¹⁾ = (362+385+432+341)/4 = 380
S₇⁽²⁾ = (380+385+391+407.5)/4 = 390.88
a₇ = 2(407.50) − 390.88 = 424.13
b₇ = (2/3)(407.50 − 390.88) = 11.08
F₈ = a₇ + b₇(1) = 424.13 + 11.08 = 435.21

F₂₁ = a₂₀ + b₂₀(1) = 700.88 + 17.25 = 718.13  → ≈ 718 เล่ม
F₂₂ = a₂₀ + b₂₀(2) = 700.88 + 17.25×2 = 735.38 → ≈ 735 เล่ม
```

### 2.4 Single Exponential Smoothing (การเรียบแบบเอ็กซ์โพเนนเชียลอย่างง่าย)

> 💡 **Intuition:** ลองนึกว่าเราประมาณค่าวันพรุ่งนี้โดย "ผสม" ค่าที่วัดได้วันนี้กับค่าพยากรณ์ที่เคยคาดไว้ โดยให้วันนี้มีน้ำหนัก α ส่วนที่เหลือคือประวัติที่สะสมมา ข้อมูลที่เก่ากว่าจะมีน้ำหนักลดลงทีละน้อยเรื่อย ๆ จุดที่อุปมาจะพัง: SES ไม่จับ Trend หรือ Seasonality (ค่าพยากรณ์จะเป็นระดับเดิมซ้ำ) จึงเหมาะกับข้อมูลที่ไม่มี Trend ชัด
> [Source: generated — not verified against original document]

#### แนวคิด
วิธี **Single Exponential Smoothing** คือการคำนวณค่าเฉลี่ยถ่วงน้ำหนัก โดยให้น้ำหนัก **α (Alpha)** กับข้อมูลล่าสุด มากที่สุด แล้วน้ำหนักจะลดลงแบบ Exponential เมื่อข้อมูลมีความเก่ามากขึ้น

- **α ใกล้ 1** (เช่น 0.7-0.9): ให้น้ำหนักข้อมูลล่าสุดมาก → ตอบสนองเร็ว แต่ผันผวน
- **α ใกล้ 0** (เช่น 0.05-0.2): ให้น้ำหนักข้อมูลเก่ามาก → เรียบขึ้น แต่ตอบสนองช้า

#### ขั้นตอนการหาค่าพยากรณ์

```
STEP 1: กำหนดค่าน้ำหนัก α อยู่ระหว่าง 0-1
        ในปฏิบัติ ทดลองใช้หลายค่า (เช่น 0.1-0.3) แล้วเลือก α ที่ให้ MSE/MAE ต่ำสุด

STEP 2: กำหนดค่าเริ่มต้น F₂ = Y₁ (ใช้ข้อมูลแรก)

STEP 3: คำนวณค่าพยากรณ์จากสูตร
        Fₜ₊₁ = α·Yₜ + (1-α)·Fₜ
        
        ตัวอย่าง: α = 0.2, Y₁ = 5.4, Y₂ = 5.3
        F₂ = Y₁ = 5.4
        F₃ = 0.2(5.3) + 0.8(5.4) = 1.06 + 4.32 = 5.38
        F₄ = 0.2(5.3) + 0.8(5.38) = 1.06 + 4.304 = 5.364 ≈ 5.36
```

#### สูตรที่ขยายออก
```
Fₜ₊₁ = α·Yₜ + α(1-α)·Yₜ₋₁ + α(1-α)²·Yₜ₋₂ + ...
```
แสดงว่าน้ำหนัก **α** ลดลงแบบ exponential ตามอายุของข้อมูล

#### ตัวอย่างการคำนวณ (α = 0.2)

| ไตรมาส | ข้อมูล (Yₜ) | พยากรณ์ (Fₜ) | Error (Eₜ) | \|Eₜ\| | Eₜ² |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 5.4 | - | - | - | - |
| 2 | 5.3 | 5.40 | -0.10 | 0.10 | 0.01 |
| 3 | 5.3 | 5.38 | -0.08 | 0.08 | 0.01 |
| 4 | 5.6 | 5.36 | +0.24 | 0.24 | 0.06 |
| 5 | 6.9 | 5.41 | +1.49 | 1.49 | 2.22 |
| 6 | 7.2 | 5.71 | +1.49 | 1.49 | 2.22 |
| 7 | 7.2 | 6.01 | +1.19 | 1.19 | 1.42 |
| 8 | - | 6.25 | - | - | - |

**ค่าพยากรณ์ไตรมาส 8:** F₈ = 0.2(7.2) + 0.8(6.01) = 1.44 + 4.81 = 6.25

**🧭 ทำความเข้าใจ** _[Source: generated — not verified against original document]_

**แตกวลีสำคัญ:**
- "α (Alpha)" → น้ำหนักที่ให้ข้อมูลล่าสุด (ค่าระหว่าง 0–1) ยิ่งใกล้ 1 ยิ่งตอบสนองเร็ว
- "(1−α)·Fₜ" → น้ำหนักที่ให้ค่าพยากรณ์เดิม ซึ่งสะสมประวัติของข้อมูลไว้
- "Fₜ₊₁ = α·Yₜ + (1−α)·Fₜ" → ค่าพยากรณ์ใหม่ = ผสมข้อมูลล่าสุดกับค่าพยากรณ์เดิม
- "F₂ = Y₁" → ค่าเริ่มต้น ใช้ข้อมูลแรกเป็นพยากรณ์รอบแรก

**ตัวอย่าง:**
- ✅ α = 0.2 (น้ำหนักล่าสุดน้อย) → F₄ = 5.36 เรียบ ไม่กระโดดตาม Y₄ = 5.6 มากนัก
- ❌ ตั้ง α = 0.9 แล้วคาดว่าจะได้ค่าเรียบเหมือน α = 0.2 → ผิด เพราะ α สูงให้น้ำหนักข้อมูลล่าสุดมาก ค่าพยากรณ์จึงขยับตามข้อมูลและแกว่งมากกว่า
- **ต่างกันตรง:** α ต่ำ = เรียบแต่ตอบสนองช้า; α สูง = ตอบสนองเร็วแต่ผันผวน

**อย่าสับสน:** α ในการเรียบ (smoothing constant) ไม่เกี่ยวกับ α ระดับนัยสำคัญในการทดสอบสมมติฐาน แม้จะใช้สัญลักษณ์เดียวกัน

**เช็คความเข้าใจ:** ใช้ตัวอย่างเดิม (Y₁ = 5.4, Y₂ = 5.3) ถ้าเปลี่ยนเป็น α = 0.8 แล้ว F₃ เท่าไร และเข้าใกล้ Y₂ หรือ F₂ มากกว่ากัน

<details><summary>เฉลย</summary>

F₃ = 0.8(5.3) + 0.2(5.4) = 4.24 + 1.08 = 5.32 ซึ่งเข้าใกล้ Y₂ = 5.3 มากกว่า F₂ = 5.4 (เทียบกับ α = 0.2 ที่ได้ 5.38) เพราะ α สูงให้น้ำหนักข้อมูลล่าสุดมากขึ้น
</details>

### 2.5 Double Exponential Smoothing (Brown's Method)

#### เมื่อใช้
ข้อมูลที่มี **Linear Trend แต่ไม่มี Seasonality** (ดู Chapter 10 ตัวอย่างยอดขาย 1960-1978)

#### ขั้นตอนการหาค่าพยากรณ์

```
STEP 1: กำหนด α (ปกติ 0.05-0.1 เล็กกว่า Single Method)

STEP 2: คำนวณค่าเฉลี่ยทำให้เรียบครั้งแรก
        Sₜ⁽¹⁾ = α·Yₜ + (1-α)·Sₜ₋₁⁽¹⁾

STEP 3: คำนวณค่าเฉลี่ยทำให้เรียบครั้งที่สอง
        Sₜ⁽²⁾ = α·Sₜ⁽¹⁾ + (1-α)·Sₜ₋₁⁽²⁾

STEP 4: ประมาณค่าพารามิเตอร์ Trend
        aₜ = 2·Sₜ⁽¹⁾ - Sₜ⁽²⁾       (ระดับ)
        bₜ = [α/(1-α)]·(Sₜ⁽¹⁾ - Sₜ⁽²⁾)  (Slope/Trend)

STEP 5: คำนวณค่าพยากรณ์
        Fₜ₊ₘ = aₜ + bₜ·m
        
        โดย m = จำนวนก้าวข้างหน้า
        F₈ (1 ก้าว) = a₇ + b₇(1)
        F₉ (2 ก้าว) = a₇ + b₇(2)
```

#### ตัวอย่างจากสไลด์ (ข้อมูล 20 ช่วงเวลา, ค่าเริ่มต้น Y₁ = S₁⁽¹⁾ = S₁⁽²⁾ = 114)

```text
F₃  = a₂  + b₂(1)  = 115.52 + 0.08(1) = 115.6
F₂₁ = a₂₀ + b₂₀(1) = 176.79 + 2.48(1) = 179.27
F₂₂ = a₂₀ + b₂₀(2) = 176.79 + 2.48(2) = 181.75
```

**🧭 ทำความเข้าใจ** _[Source: generated — not verified against original document]_

**แตกวลีสำคัญ:**
- "เรียบสองครั้ง" → ครั้งแรก $S_t^{(1)}$ = smoothed value, ครั้งที่สอง $S_t^{(2)}$ = smoothed ของ $S_t^{(1)}$ = จับ Trend ได้ดีขึ้น
- "$a_t$" → ระดับปัจจุบัน (Level) หลังปรับเรียบแล้ว
- "$b_t$" → ความชัน (Slope/Trend) = อัตราการเปลี่ยนแปลงต่อช่วงเวลา
- "$F_{t+m} = a_t + b_t \cdot m$" → ทำนาย m ก้าว = ระดับปัจจุบัน + (ความชัน × จำนวนก้าว)

**ตัวอย่าง:**
- ✅ ข้อมูล 20 ช่วงเวลา (Y₁ = 114) มี Trend ↑ — Brown's method จะจับ $a_{20}=176.79$ และ $b_{20}=2.48$ → ทำนาย $F_{21}=179.27$, $F_{22}=181.75$ ชัดเจน
- ❌ ข้อมูลขึ้นลงแบบสุ่ม ไม่มี Trend จริง — Brown's จะประมาณ bₜ จาก noise แล้วยื่น Trend ปลอมไปข้างหน้า → ทำนายผิด
- **ต่างกันตรง:** Single Exponential เรียบแค่ level; Brown's Double เรียบและจับ slope

**อย่าสับสน:** "Double Exponential (Brown's)" กับ "Double Moving Average" = วิธีต่างกัน — อันแรกใช้ exponential weight, อันหลังใช้ MA สองครั้ง

**เช็คความเข้าใจ:** ถ้า Brown's ได้ $a_{20}=176.79$ และ $b_{20}=2.48$ จงหา $F_{23}$ (3 ก้าวข้างหน้า)
<details><summary>เฉลย</summary>

$F_{23} = 176.79 + 2.48 \times 3 = 184.23$
</details>

> สไลด์ให้เฉพาะผลลัพธ์ตัวอย่างนี้ (ไม่ระบุค่า α ที่ใช้และข้อมูลดิบทั้งชุด) จึงไม่แสดงขั้นกลาง
> ส่วนตัวอย่างร้านหนังสือ N=4 (S⁽¹⁾ = 407.50 ฯลฯ) เป็นของ **Double Moving Average** ดูหัวข้อ 2.3

### 2.6 Triple Exponential Smoothing — Holt-Winters Method

#### เมื่อใช้
ข้อมูลที่มี **Trend AND Seasonality** (เช่น ยอดขายที่มี Pattern ฤดูกาลชัดเจน: Q1 ขายต่ำ, Q4 ขายสูง)

> 💡 **Intuition:** ลองนึกถึง Brown's Double Exponential ว่า "จับ Trend เชิงเส้น" แต่จำลองไม่ได้ว่าขาย Q1 ต่ำเสมอ Q4 สูงเสมอ (Seasonality ซ้ำตามรอบปี) Holt-Winters เพิ่มตัวแปรที่สามเข้าไป ("Seasonality") เพื่อจำลอง Pattern ฤดูกาลนี้ — เช่นในตัวอย่าง Q3 = 113.7% ของ Level, Q4 = 89.7% มันจำ Pattern นี้ซ้ำ และประยุกต์เมื่อทำนายปีหน้า ทำให้แม่นมากขึ้น หมายเหตุ: ผลฤดูกาลมี 2 แบบ — Multiplicative เป็น % ของ Level, Additive เป็นค่าคงที่
> [Source: generated — not verified against original document]

#### องค์ประกอบหลัก 3 ตัว

| องค์ประกอบ | สัญลักษณ์ | ความหมาย |
| :--- | :--- | :--- |
| **Level** | Lₜ | ระดับพื้นฐาน (หลังหักอิทธิพล Trend และ Seasonality) |
| **Trend** | bₜ | ทิศทาง/อัตราการเปลี่ยนแปลง (เพิ่มขึ้นหรือลดลง) |
| **Seasonality** | Sₜ | Pattern ซ้ำตามรอบเวลา (รายไตรมาส รายเดือน) |

#### สองรูปแบบ

**1. Multiplicative (คูณ)** — ฤดูกาลแปรผันตามระดับ
```
ข้อมูล = Level × Trend × Seasonality

เหมาะ: ขายดีช่วงฤดูกาลที่ดี แต่ขนาด % คงที่
ตัวอย่าง: ถ้า Level เพิ่ม 2 เท่า ฤดูกาลก็เพิ่ม 2 เท่า
```

**2. Additive (บวก)** — ฤดูกาลคงที่
```
ข้อมูล = Level + Trend + Seasonality

เหมาะ: ข้อมูลที่ฤดูกาล Impact คงที่ไม่เปลี่ยน
ตัวอย่าง: ตลอดปี ช่วงเทศกาลขายเพิ่ม 500 บาทเท่าเดิม
```

**🧭 ทำความเข้าใจ** _[Source: generated — not verified against original document]_

**แตกวลีสำคัญ:**
- "Multiplicative (คูณ)" → ผลฤดูกาลเป็นสัดส่วน (%) ของ Level จึงขยับตามระดับของข้อมูล
- "Additive (บวก)" → ผลฤดูกาลเป็นค่าคงที่ที่บวกเข้าไป ไม่ขึ้นกับระดับ Level
- "ข้อมูล = Level × Trend × Seasonality" → สูตรแบบคูณ
- "ข้อมูล = Level + Trend + Seasonality" → สูตรแบบบวก

**ตัวอย่าง:**
- ✅ ยอดขายช่วงเทศกาลขยายตามยอดรวมของร้านที่โตขึ้น (สัดส่วนคงที่) → ใช้ Multiplicative
- ✅ ช่วงเทศกาลขายเพิ่มคงที่ 500 บาททุกปี ไม่ว่ายอดรวมจะเป็นเท่าไร → ใช้ Additive (ตามตัวอย่างในโน้ต)
- ❌ ใช้ Additive กับข้อมูลที่ผลฤดูกาลขยายตามระดับที่โตขึ้นเรื่อย ๆ → เลือกรูปแบบผิด ควรใช้ Multiplicative
- **ต่างกันตรง:** ถามว่า "ผลฤดูกาลเป็น % ของระดับ (คูณ) หรือเป็นจำนวนคงที่ (บวก)"

**อย่าสับสน:** Multiplicative ไม่ได้หมายถึง "ฤดูกาลเป็น 2 เท่าเสมอ" แต่หมายถึงสัดส่วนคงที่ต่อระดับ (เช่น Q3 = 113.7% ของ Level ตามโน้ต)

**เช็คความเข้าใจ:** ยอดขายโตขึ้น 2 เท่า แต่ผลฤดูกาลยังเพิ่มเท่าเดิม 500 บาท ควรเลือกรูปแบบใด และเพราะอะไร

<details><summary>เฉลย</summary>

ใช้ **Additive** เพราะผลฤดูกาลเป็นค่าคงที่ไม่ขึ้นกับระดับ ถ้าผลฤดูกาลขยายตามระดับ (เป็นสัดส่วน) จึงจะเป็น Multiplicative
</details>

#### Holt-Winters Multiplicative (สูตรปกติ)

```
พารามิเตอร์ 3 ตัว:
- α = ค่าคงที่ทำให้เรียบ Level (0 < α < 1)
- γ = ค่าคงที่ทำให้เรียบ Trend (0 < γ < 1)
- β = ค่าคงที่ทำให้เรียบ Seasonality (0 < β < 1)
(สัญลักษณ์ตามสไลด์ — ตำราอื่นอาจสลับ β/γ)

สูตรการอัปเดต:
Lₜ = α(Yₜ / Sₜ₋ₛ) + (1-α)(Lₜ₋₁ + bₜ₋₁)
bₜ = γ(Lₜ - Lₜ₋₁) + (1-γ)bₜ₋₁
Sₜ = β(Yₜ / Lₜ) + (1-β)Sₜ₋ₛ

ค่าพยากรณ์:
Fₜ₊ₘ = (Lₜ + bₜ·m) × Sₜ₋ₛ₊ₘ

เมื่อ:
- s = จำนวนฤดูกาลใน 1 ปี (เช่น 4 สำหรับไตรมาส, 12 สำหรับเดือน)
- m = จำนวนก้าวข้างหน้า
```

#### ค่าเริ่มต้น (Initialization)

```
STEP 1: Level ครั้งแรก
        Lₛ = (Y₁ + Y₂ + ... + Yₛ) / s
        
        ตัวอย่าง (s=4): L₄ = (362+385+432+341)/4 = 380

STEP 2: Trend ครั้งแรก
        bₛ = (1/s) × [ (Yₛ₊₁-Y₁)/s + (Yₛ₊₂-Y₂)/s + ... + (Y₂ₛ-Yₛ)/s ]

STEP 3: Seasonality
        Sᵢ = Yᵢ / Lₛ,  i = 1, 2, ..., s
        
        ตัวอย่าง:
        S₁ = Y₁/L₄ = 362/380 = 0.953
        S₂ = Y₂/L₄ = 385/380 = 1.013
        S₃ = Y₃/L₄ = 432/380 = 1.137
        S₄ = Y₄/L₄ = 341/380 = 0.897
```

**🧭 ทำความเข้าใจ** _[Source: generated — not verified against original document]_

**แตกวลีสำคัญ:**
- "Level ($L_t$)" → ระดับพื้นฐานของข้อมูล (หลังหักอิทธิพล Trend และ Seasonality)
- "Trend ($b_t$)" → ความชัน/ทิศทาง = อัตราการเปลี่ยนแปลง (ต่อช่วงเวลา)
- "Seasonality ($S_t$)" → ปัจจัยซ้ำตามรอบ (เช่น Q1=0.953, Q4=0.897) = สัดส่วนต่อ Level (Multiplicative)
- "Multiplicative" → ข้อมูล = Level × Trend × Seasonality (ฤดูกาล impact = % ของ level, เล็กกว่าถ้า level เล็ก)
- "Additive" → ข้อมูล = Level + Trend + Seasonality (ฤดูกาล impact = ค่าคงที่เสมอ)

**ตัวอย่าง:**
- ✅ ยอดขายเสื้อ: Q1 ต่ำ, Q2 ปานกลาง, Q3 สูง, Q4 สูงสุด และยอดรวมโตขึ้นทุกปี → Trend ↑ + Seasonality ซ้ำทุกปี และส่วนต่างฤดูกาล (หน่วยจริง) ขยายตาม Level → Holt-Winters Multiplicative
- ❌ ถ้าใช้ Brown's Double (ไม่มี Seasonality) → Brown's ให้ค่าพยากรณ์เป็นเส้นตรงตาม Trend ทุกไตรมาส พลาด pattern ฤดูกาล → error ใหญ่เป็นรอบ
- **ต่างกันตรง:** Brown's = 1 พารามิเตอร์ ($\alpha$) ใช้ทั้งสองรอบการเรียบ; Holt-Winters = 3 พารามิเตอร์ ($\alpha$ Level, $\gamma$ Trend, $\beta$ Seasonality ตามสัญลักษณ์สไลด์)

**อย่าสับสน:** "Multiplicative" = ฤดูกาล impact ขึ้นอยู่กับ Level (ถ้า Level สูงขึ้น ผลฤดูกาลเป็นหน่วยจริงใหญ่ขึ้น แต่ % คงที่); "Additive" = ฤดูกาล impact คงที่ไม่เปลี่ยน (เช่น ช่วงเทศกาลขายเพิ่ม 500 บาทเท่าเดิมทุกปี)

**เช็คความเข้าใจ:** Multiplicative Holt-Winters: $L_4=380$, $b_4=9.75$, $S_1=0.953$, $S_2=1.013$ จงหา $F_5$ (1 ก้าวข้างหน้า จาก t=4)
<details><summary>เฉลย</summary>

$F_5 = (L_4 + b_4 \cdot 1) \times S_{4-4+1} = (380 + 9.75) \times S_1 = 389.75 \times 0.953 \approx 371.4$ (ใช้ $S_1 = 362/380 = 0.95263$ ไม่ปัด → 371.29 ตรงกับตารางสไลด์)
</details>

### 2.7 เปรียบเทียบ Moving Average vs Exponential Smoothing

> 💡 **Intuition:** ลองนึกว่า MA เหมือนคนที่จำแค่ N วันล่าสุด และลืมทุกอย่างที่เก่ากว่านั้นทันที ส่วน Exponential Smoothing จำทุกวันตั้งแต่เริ่ม แต่ให้น้ำหนักวันเก่ามากค่อย ๆ ลดลง ความต่างนี้ทำให้ผลต่างกันทั้งเรื่องความไวต่อการเปลี่ยนแปลง (Lag) และการจับ Trend/Seasonality จุดที่อุปมาจะพัง: ความจำที่ "ไม่ลืม" ของ ES ไม่ได้แปลว่าดีกว่าเสมอไป ขึ้นอยู่กับลักษณะของข้อมูล
> [Source: generated — not verified against original document]

| ลักษณะ | Moving Average | Exponential Smoothing |
| :--- | :--- | :--- |
| **ลำดับเทอม** | ใช้ N เทอมล่าสุดเท่านั้น | ใช้ข้อมูลทั้งหมดตั้งแต่เริ่มต้น |
| **น้ำหนัก** | เท่ากันทั้งหมด | Exponential (ล่าสุดมากสุด) |
| **การตอบสนอง** | ช้า (lag มาก) | เร็ว (lag น้อย) |
| **ความเรียบ** | ขึ้นอยู่กับ N | ขึ้นอยู่กับ α |
| **Trend** | ผ่อนลง | ติดตาม |
| **Seasonality** | ไม่สามารถจำลอง | สามารถจำลอง (Triple) |

**🧭 ทำความเข้าใจ** _[Source: generated — not verified against original document]_

**แตกวลีสำคัญ:**
- "Lag" → พยากรณ์ตามหลังข้อมูลจริง (การตอบสนองช้า)
- "ใช้ N เทอมล่าสุดเท่านั้น" (MA) vs "ใช้ข้อมูลทั้งหมดตั้งแต่เริ่มต้น" (ES) → MA ตัดข้อมูลที่เก่ากว่า N ทิ้ง ส่วน ES เก็บไว้แต่ลดน้ำหนักลง
- "Triple" → Exponential Smoothing รุ่นที่สาม (Holt-Winters) ที่มีองค์ประกอบ Seasonality

**ตัวอย่าง:**
- ✅ ข้อมูลแกว่งรอบระดับคงที่ → MA หรือ SES ใช้ได้ (เลือกตามความไวที่ต้องการ)
- ❌ เลือก MA เพื่อจับ Seasonality → ทำไม่ได้ตามตาราง ต้องใช้ Triple (Holt-Winters)
- **ต่างกันตรง:** MA ตัดข้อมูลนอกช่วง N ทิ้ง ส่วน ES ลดน้ำหนักข้อมูลเก่าแทนการตัดทิ้ง

**อย่าสับสน:** "Exponential" ไม่ได้หมายความว่าค่าพยากรณ์เพิ่มแบบ exponential แต่หมายถึงน้ำหนักของข้อมูลที่ลดลงแบบเลขยกกำลังตามอายุของข้อมูล

**เช็คความเข้าใจ:** ข้อมูลมีทั้ง Trend และ Seasonality ชัด ควรเลือกวิธีใดจากสองกลุ่ม และเพราะอะไร

<details><summary>เฉลย</summary>

ใช้ Exponential Smoothing แบบ Triple (Holt-Winters) เพราะ MA จำลอง Seasonality ไม่ได้ และในตารางการเปรียบเทียบ MA จับ Trend ได้แค่ผ่อนลง ไม่ได้ติดตามอย่าง ES
</details>

## Part 3: Quick Reference & Exam Cheat Sheet

### Checklist สรุปหัวใจสำคัญก่อนสอบ

* [ ] **Single Exponential:** Fₜ₊₁ = αYₜ + (1-α)Fₜ — เลือก α (ปกติ 0.1-0.3)
* [ ] **Double Exponential:** คำนวณ Sₜ⁽¹⁾ → Sₜ⁽²⁾ → aₜ, bₜ → Fₜ₊ₘ — เหมาะ Trend เชิงเส้น
* [ ] **Triple (Holt-Winters):** เพิ่ม Seasonality → 3 พารามิเตอร์ (α, β, γ)
* [ ] **Multiplicative vs Additive:** คูณ (ฤดูกาลแปรผัน) vs บวก (ฤดูกาลคงที่)
* [ ] **ค่า m:** m=1 → 1 ก้าว, m=2 → 2 ก้าว
* [ ] **MSE/MAE:** เลือก α ที่ให้ Error ต่ำสุด

### สรุปสูตรสำคัญ

| สูตร | ความหมาย |
| :--- | :--- |
| `Fₜ₊₁ = αYₜ + (1-α)Fₜ` | Single Exponential |
| `Sₜ⁽¹⁾ = αYₜ + (1-α)Sₜ₋₁⁽¹⁾` | Double — ครั้งแรก |
| `Sₜ⁽²⁾ = αSₜ⁽¹⁾ + (1-α)Sₜ₋₁⁽²⁾` | Double — ครั้งที่สอง |
| `aₜ = 2Sₜ⁽¹⁾ - Sₜ⁽²⁾` | Level (Double) |
| `bₜ = [α/(1-α)](Sₜ⁽¹⁾ - Sₜ⁽²⁾)` | Slope/Trend (Double) |
| `Fₜ₊ₘ = aₜ + bₜ·m` | Forecast m ก้าวข้างหน้า (Double) |
| `Fₜ₊ₘ = (Lₜ + bₜ·m)·Sₜ₋ₛ₊ₘ` | Forecast (Holt-Winters Multiplicative) |

### Concept Map

```text
Exponential Smoothing Methods
├── Single Exponential
│   ├── Horizontal Data (ไม่มี Trend)
│   ├── α ∈ (0, 1)
│   └── Fₜ₊₁ = αYₜ + (1-α)Fₜ
│
├── Double Exponential (Brown's)
│   ├── Linear Trend Data
│   ├── คำนวณ 2 ครั้ง: Sₜ⁽¹⁾, Sₜ⁽²⁾
│   └── Fₜ₊ₘ = aₜ + bₜ·m
│
└── Triple Exponential (Holt-Winters)
    ├── Trend + Seasonality
    ├── 3 พารามิเตอร์: α, β, γ
    ├── 2 รูปแบบ: Multiplicative / Additive
    └── Fₜ₊ₘ = (Lₜ + bₜ·m)·Sₜ₋ₛ₊ₘ
```

## ⚠️ Common Pitfalls & Exam Traps

* **α ไม่มีค่า \"ถูก\":** ต้อง optimize (ทดลองหลายค่า) เลือกค่าที่ให้ MSE/MAE ต่ำสุด — ไม่มีค่า universal
* **Exponential ≠ ชัวร์ดีกว่า Moving Average เสมอ:** สำหรับข้อมูล Horizontal ธรรมดา Moving Average บางที ง่ายกว่าและเพียงพอ
* **ค่าเริ่มต้น Lₛ ใน Holt-Winters:** ต้องอาศัยข้อมูล s ไตรมาสแรกมาคำนวณ — ไม่ใช่ก็ได้เอา Naive
* **s = ความยาวฤดูกาล:** ถ้าข้อมูลรายเดือน s=12; รายไตรมาส s=4; รายปี s=1 (ไม่มี seasonality)
* **Multiplicative ÷ 0:** ถ้า Yₜ = 0 จะเกิด division by zero — อาจต้องปรับ data หรือใช้ additive แทน
* **ความแนน Exponential:** ที่ชื่อ \"Exponential\" ไม่ได้หมายถึง exponential function แต่หมายถึงน้ำหนักลดลงแบบ exponential
