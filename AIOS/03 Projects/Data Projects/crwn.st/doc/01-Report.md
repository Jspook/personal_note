# โครงงานวิชา Fundamental Web Programming
**รายงานเชิงเทคนิค (Technical Report)**

## 1. องค์ประกอบเชิงสถาปัตยกรรมของเว็บไซต์ที่สร้างขึ้น
ระบบ crwn.st (E-commerce & Fitting Room System) ถูกออกแบบโดยใช้สถาปัตยกรรมแบบ Client-Server Architecture ซึ่งประกอบไปด้วย:

- **Frontend (Client-side):**
  - พัฒนาด้วยเทคโนโลยี HTML, CSS และ JavaScript
  - ใช้ **Tailwind CSS** (ผ่าน CDN) ในการออกแบบ UI ให้สวยงามและ Responsive
  - มีการใช้ **Optimistic UI** ในฝั่งตะกร้าสินค้า เพื่อให้ระบบทำงานและตอบสนองผู้ใช้ได้อย่างรวดเร็ว
  - สื่อสารกับ Server ผ่าน Fetch API แบบ Asynchronous (AJAX)

- **Backend (Server-side):**
  - พัฒนาด้วย **Node.js** และเฟรมเวิร์ก **Express.js** 
  - ใช้ **EJS (Embedded JavaScript templating)** ในการทำ Server-Side Rendering สร้างหน้าเว็บเพจแบบไดนามิก
  - จัดการเซสชันด้วย **JWT (JSON Web Tokens)** ผ่านคุกกี้ (Cookie-parser)

- **Database:**
  - ใช้ระบบฐานข้อมูลแบบ Relational Database คือ **MySQL**
  - มีการจัดกลุ่มการทำงานเป็น Transaction ในส่วนของการตัดสต็อกสินค้าและชำระเงินเพื่อความถูกต้องของข้อมูล (Atomic operations)

## 2. เทคนิคและวิธีการในการสร้างองค์ประกอบเว็บไซต์แต่ละส่วน

### 2.1 ระบบห้องลองเสื้อผ้า (Fitting Room Management)
- **เทคโนโลยีที่ใช้:** Express.js + MySQL + Vanilla JavaScript
- **อธิบาย:** ระบบจำลองการลองเสื้อผ้าที่ลูกค้าสามารถหยิบสินค้าใส่ห้องลองได้ พนักงานห้องลองสามารถยืนยันสถานะ และระบบจะมีการล็อก (Lock) สถานะห้องลองแบบ Real-time เพื่อป้องกันการใช้งานซ้ำซ้อน มีการใช้ `localStorage` ร่วมกับการดึงสถานะจาก API ฝั่งเซิร์ฟเวอร์เพื่อให้ข้อมูลสอดคล้องกัน

### 2.2 ระบบตะกร้าสินค้าและคำนวณราคา (Cart & Checkout)
- **เทคโนโลยีที่ใช้:** Fetch API, Optimistic UI
- **อธิบาย:** เมื่อลูกค้าแก้ไขจำนวนสินค้าในตะกร้า หน้าจอจะคำนวณและแสดงผลราคารวมทันที (Optimistic) จากนั้นส่งข้อมูลแบบ Background ไปบันทึกที่เซิร์ฟเวอร์ ทำให้ผู้ใช้รู้สึกว่าระบบลื่นไหลไม่มีสะดุด 

### 2.3 การเชื่อมต่อฐานข้อมูลและการตัดสต็อก
- **เทคโนโลยีที่ใช้:** `mysql2/promise`, MySQL Transactions
- **อธิบาย:** การชำระเงินและออกใบเสร็จ (Receipt) จะถูกครอบด้วย `Transaction` หากเกิดข้อผิดพลาด หรือสินค้าหมดสต็อกในขณะที่กดจ่ายเงิน ระบบจะ `Rollback` ไม่ให้เกิดข้อมูลที่ผิดพลาด นอกจากนี้ยังมีการ Aggregate สินค้าชนิดเดียวกันเข้าด้วยกันก่อนทำการอัปเดตสต็อกเพื่อความแม่นยำ

## 3. การออกแบบฐานข้อมูล (Database Design)

ระบบมีการออกแบบฐานข้อมูลเพื่อรองรับ E-commerce ดังนี้:
1. **CUSTOMER**: เก็บข้อมูลลูกค้า (ID, ชื่อ, สกุล, โทรศัพท์, อีเมล, รหัสผ่านแบบ Hash)
2. **EMPLOYEE**: เก็บข้อมูลพนักงาน (ID, ชื่อ, บทบาท Cashier หรือ Fitting Staff)
3. **ITEM & ITEM_VARIANT**: เก็บข้อมูลสินค้าและตัวเลือก (SKU, ขนาด, สี, สต็อก)
4. **LOCATION**: เก็บข้อมูลจุดที่วางสินค้าในร้าน
5. **PAY_CART & PAY_CART_ITEM**: จัดการข้อมูลตะกร้าสินค้าชั่วคราว
6. **RECEIPT & RECEIPT_ITEM**: เก็บข้อมูลใบเสร็จหลังจากชำระเงินเสร็จสิ้น
7. **FITTING_ROOM**: จัดการสถานะและประวัติการใช้ห้องลอง

## 4. อื่นๆ
- **ระบบความปลอดภัย:** รหัสผ่านของผู้ใช้และพนักงานจะถูกนำไป Hash ด้วยไลบรารี `bcryptjs` ก่อนบันทึกลงฐานข้อมูล
- **การจัดการเวลา:** ระบบจะมีการตรวจสอบ Timezone ให้เป็น `Asia/Bangkok` เพื่อให้เวลาในใบเสร็จตรงกับความเป็นจริงเสมอ
